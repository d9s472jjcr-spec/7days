# PWA 6.0.0 実装前変更一覧

## 1. 文書状態

- 状態: 仕様承認済み・PWA実装済み・画像生成GPT変更済み・公開実施
- 対象: 公開PWAと非公開の画像生成GPT
- 作成日: 2026-08-13
- 現行PWA: 6.0.0
- 完了: 仕様承認、PWAソース編集、自動試験42件、ローカル表示確認、画像生成GPT設定変更、コミット、マージ、公開
- 未実施: 6.0.0と変更後GPTを組み合わせた生成画像試験、iPhone 16実機Safari確認

この文書は、PWAと画像生成GPTの責任範囲を整理し、実装前に変更内容を確認するための公開可能な一覧である。非公開GPTのInstructions・Knowledge本文、編集用・共有用リンク、認証情報は記録しない。

## 2. 変更目的

1. 撮影設定をPWAで明示的に選択し、画像生成GPTの暗黙の既定値へ依存しない。
2. 指示文の全行で主語と述語を明確にし、名詞だけの断片や曖昧な係り受けをなくす。
3. PWAと画像生成GPTの重複・矛盾を解消し、PWAを設定の正本、GPTを生成品質制御の正本とする。
4. iPhone 16で長いフォームを操作しやすいUIへ改善する。
5. 全項目・全選択肢・全条件分岐を自動試験できる状態にする。

## 3. 責任分担

### 3.1 PWAが管理する情報

- 被写体、画像形式、人物の固定条件
- バスト、ヒップ
- 衣装タイプ、衣装構成、衣装各部、配色、装飾、靴
- 髪、前髪、瞳、表情
- ポーズ、構図、カメラアングル、背景、照明
- 画像比率、接地影、禁止要素
- 各設定の初期値と指示文の文章形式

### 3.2 画像生成GPTが管理する情報

- 顔、肌、髪、瞳の描写品質
- 人体、関節、手指、身体接続の品質
- 指定されたバストとヒップを独立して成立させる補助規則
- 衣装の素材感、着用状態、身体との境界の品質
- 下着・水着を一般向けの商品着用写真として安全に扱う規則
- 不自然または挑発的な演出を勝手に追加しない規則
- 入力の復唱を行わず、画像を1枚生成する動作
- 再生成および部分変更時に、変更対象以外を維持する動作

PWAが明示する撮影条件を、GPT側の通常時の既定値で上書きしない。

## 4. PWAの固定出力

指示文の冒頭は次の文章へ変更する。

```text
この入力は、画像の新規生成を指示するものとする。
生成する画像は、フォトリアル画像とする。
被写体は、架空の20代の成人日本人女性1人とする。
人物の容姿は、美人とする。
人物の体型は、脚の長いモデル体型とする。
```

指示文の末尾には次の固定条件を出力する。

```text
画像の縦横比は、縦長の9:16とする。
画像には、文字、ロゴ、透かし、余分な人物および不要な小物を入れない。
```

接地影は構図に応じて条件分岐する。

- 全身: `人物の足元には、ごく薄い自然な接地影を入れる。`
- 太もも上、腰上、バストアップ: 足元が画面外になるため出力しない。

椅子に座るポーズや施設背景など、選択内容を成立させるために必要な椅子、家具、設備は「不要な小物」に含めない。

## 5. 全項目の指示文規則

### 5.1 人物

```text
人物のバストは、{バスト}とする。
人物のヒップは、{ヒップ}とする。
```

初期値は現行どおりとする。

- バスト: 豊かなバスト（89cm相当）
- ヒップ: 標準的なヒップ（85cm相当）

### 5.2 衣装

```text
人物が着用する衣装のタイプは、{衣装タイプ}とする。
衣装の構成は、{衣装構成}とする。
人物が着用するアウターは、{色}の{アウター詳細名}とする。
人物が着用するトップスは、{色}の{トップス詳細名}とする。
人物が着用するボトムスは、{色}の{ボトムス詳細名}とする。
人物が着用する衣装は、{色}の{上下一体衣装詳細名}とする。
人物が履く靴は、{色}の{靴詳細名}とする。
人物の足元は、裸足とする。
```

条件分岐は次のとおりとする。

- アウターが「無し」の場合、アウターとアウター色の文を出力しない。
- 上下分離の場合、トップスとボトムスを出力し、上下一体衣装を出力しない。
- 上下一体の場合、上下一体衣装を出力し、トップスとボトムスを出力しない。
- 靴が「裸足」の場合、靴色を出力しない。

衣装装飾は次の文章へ変換する。

```text
衣装には、装飾を付けない。
衣装装飾の内容は衣装に合わせて補完し、装飾量は控えめとする。
衣装装飾の内容は衣装に合わせて補完し、装飾量は華美とする。
```

衣装の全詳細名は名詞句として保持し、上記テンプレートへ挿入する。全候補について、名称の誤記、意味の重複、丈・襟・袖・形状の矛盾がないかを再検査する。

### 5.3 髪・瞳

```text
人物の髪色は、{髪色}とする。
人物の髪型は、{髪型詳細名}とする。
人物の前髪は、{前髪}とする。
人物の瞳の色は、{瞳の色}とする。
```

共通55色の名称とHEX値は変更しない。全色を髪、瞳、衣装各部、靴へ適用できる現行仕様を維持する。

### 5.4 表情

```text
人物の表情は真剣とし、口元を自然に閉じ、目元を落ち着かせる。
人物の表情は控えめな喜びとし、口角をわずかに上げ、目元を柔らかくする。
人物の表情は控えめな怒りとし、口をわずかに結び、視線を少し鋭くし、眉の内側をわずかに下げる。
人物の表情は控えめな悲しみとし、口角と目元をわずかに下げ、眉の内側をわずかに上げる。
```

初期値は「真剣」とする。

## 7. UI変更

### 7.1 画面下部の固定操作バー

- 「指示文をコピー」と「基準設定に戻す」を、画面下部へ固定表示する。
- ボタン内に文字は表示せず、SVGアイコンだけを表示する。
- コピーは重なった用紙のアイコン、リセットは反時計回りの矢印アイコンを使用する。
- 読み上げ用名称とツールチップ相当の説明を設定する。
- iPhone 16のホームインジケーターを避け、各タップ領域を44px以上確保する。
- 固定バーによってフォーム末尾や出力欄が隠れない余白を設ける。
- コピー完了の通知と、リセットの現行動作を維持する。

### 7.2 関連項目のグループ枠

次の項目を淡い同色の枠で視覚的にまとめる。

- 人物: バスト、ヒップ
- 衣装分類: 衣装タイプ、衣装構成
- アウター: アウター、アウターの色
- トップス: トップスデザイン、トップスの色
- ボトムス: ボトムスデザイン、ボトムスの色
- 上下一体衣装: 衣装デザイン、衣装の色
- 靴: 靴、靴の色
- 髪: 髪色、髪型、前髪
- 人物演出: 表情、ポーズ
- カメラ: 構図、カメラアングル
- 撮影環境: 背景、照明

衣装装飾と瞳の色は単独表示とする。条件分岐で項目が非表示になった場合、空の枠は表示しない。

## 8. 画像生成GPTの変更要約

公開リポジトリには設定本文を保存せず、次の変更要約だけを記録する。

### 8.1 削除する通常時の既定値

PWAが必ず明示するため、GPT側の通常時の既定値から次を削除する。

- 被写体の人数、成人、日本人女性
- 画像比率
- 全身構図と余白
- 正面寄り、目線の高さ
- 自然な直立姿勢
- 純白スタジオ背景
- ニュートラルな拡散照明
- 接地影
- 文字、ロゴ、透かし、余分な人物・小物の禁止
- 未指定時に全身、純白背景、9:16を要求する内部確認

### 8.2 修正する品質規則

- PWA 6.0.0が出力する完全文章形式を正式な入力形式として認識し、旧形式の先頭4行や名詞だけの断片を前提にしない。
- モデル体型の定義から、ヒップ容量を一律に小さくする解釈を除く。
- バストとヒップは、モデル体型と独立したPWA指定として反映する。
- 手足の不自然な融合、増殖、欠損は禁止するが、選択ポーズによる自然な接触、交差、遮蔽は許容する。
- 下着・水着でも、PWAが指定した安全なポーズと構図を優先する。
- 下着・水着に対する全身・直立の固定を削除し、不自然な反り姿勢や挑発的な演出を追加しない品質規則だけを残す。
- 選択したポーズや背景に必要な椅子、家具、設備を許容し、不要な小物だけを禁止する。
- PWAで下着・水着のデザインまたは衣装装飾が明示された場合、その指定を未指定時の一般補完より優先する。

### 8.3 維持する意図的な補強

- PWAの明示指定を省略、弱化、一般化しない。
- 成人女性1人であることを生成直前に確認する。
- 顔、首、肌、髪、瞳、人体、関節、手指、衣装の品質を内部確認する。
- 顔と首の色調連続性、セミマットな肌、チークと強い光沢の抑制を維持する。
- バストとヒップを他部位の体脂肪増加へ波及させない。

### 8.4 会話のきっかけ

現行PWAと一致しない旧形式の会話のきっかけは削除する。廃止済み項目、旧衣装名、旧色名、旧髪型、旧入力形式を例示しない。

## 9. 重複・矛盾の解消表

| 対象 | 現在の問題 | 変更後 |
|---|---|---|
| ポーズ | PWAの選択とGPTの直立既定値が競合する | PWAを正本とし、GPTの通常時既定値を削除する |
| 構図 | PWAの寄り構図とGPTの全身固定が競合する | PWAを正本とし、GPTの全身固定を削除する |
| アングル | PWAの高低選択とGPTの目線高さ既定値が競合する | PWAを正本とする |
| 背景 | PWAの19背景とGPTの純白背景既定値が競合する | PWAを正本とする |
| 照明 | PWAの5照明とGPTの拡散照明既定値が競合する | PWAを正本とし、光沢抑制だけGPTへ残す |
| ヒップ | GPTのモデル体型定義が豊かなヒップを弱める | ヒップを独立指定として扱う |
| 手・腕 | 交差禁止が腕組み等を妨げる | 自然な接触・交差・遮蔽を許容する |
| 下着・水着 | GPTの直立・全身固定がPWAの撮影設定を無効化する | 安全規則を残し、PWAの撮影設定を優先する |
| 小物 | 小物禁止が椅子や施設設備と競合する | 必要な設備を許容し、不要物だけを禁止する |
| 接地影 | 寄り構図では足元が存在しない | 全身の場合だけ出力する |
| 入力判定 | GPTが旧形式の独立行を前提にすると新しい完全文章形式を見落とす | PWA 6.0.0の完全文章形式を正式入力として認識する |
| 下着・水着の補完 | GPTの未指定時補完がPWAの明示デザインを弱める可能性がある | PWAの明示デザインと装飾を優先する |
| 入力例 | GPTの旧会話例が現行PWAと不一致 | 旧例を削除する |

## 10. 保存データへの影響

- 撮影設定の項目追加、初期値変更、出力文規則変更を伴うため、保存形式をv6へ更新する。
- プロジェクト方針に従い、旧v1～v5の前回値とプリセットは移行しない。
- 初回起動時は新しい基準設定を使用する。

## 11. 自動試験

次を追加または更新する。

1. 固定文がすべて完全な文章であること。
2. 全項目・全選択肢を選んだ出力が句点で終わり、名詞だけの単独行を作らないこと。
3. すべての衣装詳細名が正しいテンプレートへ挿入されること。
4. 上下分離・上下一体・アウター有無・裸足の条件分岐が正しいこと。
5. ポーズ9種類、構図4種類、アングル3種類、背景19種類、照明5種類を必ず1件ずつ出力すること。
6. 全身以外では接地影を出力しないこと。
7. 背景文に照明、明暗、背景ぼけの指定が混入していないこと。
8. PWA 6.0.0の完全文章形式を、画像生成GPTが新規生成指示として認識すること。
9. PWAの基準設定と画像生成GPTの通常時既定値が重複しないことを、公開可能な設定要約で確認すること。
10. アイコンボタンに読み上げ名称があり、文字ラベルを表示しないこと。
11. 固定操作バーがフォーム末尾を隠さないこと。
12. 条件分岐後のグループ枠が正しく表示され、空の枠を残さないこと。
13. v6で旧保存データと旧プリセットを読み込まないこと。

## 12. 手動確認

- デスクトップの主要幅で、グループ枠、固定操作バー、色選択、条件分岐を確認する。
- iPhone 16のSafariで、ホームインジケーターとの干渉、44px以上のタップ領域、最下部項目の可視性を確認する。
- コピー、リセット、プリセット保存・読込・削除の通知と動作を確認する。
- 全身、太もも上、腰上、バストアップの指示文を画像生成GPTへ投入し、構図がGPT側の旧既定値に戻らないことを確認する。
- 立ち姿、腕組み、着座の生成結果で人体、手指、衣装の破綻を確認する。
- ユーザーが画像品質を目視し、合否を判定する。

## 13. 実施順序と承認ゲート

1. この実装前変更一覧をユーザーが確認し、仕様を承認する。
2. PWAをローカルで実装し、自動試験とローカル表示確認を行う。
3. 非公開領域へ画像生成GPT設定をバックアップし、要約とハッシュを記録する。
4. ユーザー承認済みの要約に従って画像生成GPTを変更する。
5. PWAとGPTを組み合わせた生成試験を行い、ユーザーが画像品質を判定する。
6. 文書、選択肢カタログ、版番号を更新する。
7. 差分と試験結果を報告し、マージ・公開の承認を別途得る。
8. 承認後にマージ・公開し、公開版をiPhone 16で確認する。

仕様承認、GPT設定変更、画像品質合格、マージ・公開は、それぞれ別の承認として扱う。
