# 引き継ぎガイド

## 1. 目的

この文書は、プロジェクトを初めて扱う保守担当者が、公開PWAと非公開の画像生成GPTを安全に引き継ぐための入口である。詳細仕様は `PWA_SPECIFICATION.md`、日常運用と公開・復旧は `OPERATIONS_RUNBOOK.md`、画像生成GPTの管理は `GPT_OPERATIONS.md` を正とする。

## 2. 現在の状態

| 対象 | 状態 |
|---|---|
| 公開PWA | 4.1.0、GitHub Pagesで公開中。選択肢カタログを含む |
| PWA実装・試験 | 完了。自動試験34件、PWA 4.0.1までのiPhone 16実機Safari確認合格。4.1.0は選択肢カタログ追加 |
| 画像生成GPT | 現行GPTを運用中。最終品質試験3件をユーザーが合格判定 |
| 旧・指示文生成GPT | 共有停止、完全削除、旧リンク無効化まで完了 |
| 保存形式 | v4。旧v1・v2・v3は移行しない |
| 公開方式 | `main` ブランチのリポジトリ直下をGitHub Pagesで配信 |

この表は引き継ぎ時点の記録である。作業開始時にはGitHubの最新状態、Pages設定、公開版、GPTの共有状態を再確認する。

## 3. 引き継ぎに必要な権限

GitHubとChatGPTは別系統で管理する。GitHubの権限だけでは画像生成GPTを編集できない。

- GitHubリポジトリへの書き込み権限
- GitHub Pagesとリポジトリ設定を確認できる権限
- Node.js 20以上を実行できる開発環境
- UI変更時にiPhone 16のSafariで確認できる担当者またはユーザーとの連絡経路
- 現行画像生成GPTを編集できるChatGPT側の権限
- 非公開設定バックアップへ安全にアクセスできる権限

認証情報やアカウントのパスワードを共有してはならない。ChatGPT側の共同編集・所有権・共有機能は契約や画面更新で変わり得るため、引き継ぎ時点の管理画面で確認する。

## 4. 最初の確認手順

1. リポジトリを取得し、`main`、最新コミット、未反映のPull RequestとIssueを確認する。
2. `package.json` の版とREADMEの公開版が一致することを確認する。
3. `npm test` を実行し、全試験が成功することを確認する。
4. `npm run serve` でローカル表示、指示文生成、コピー、プリセット保存・読込・削除を確認する。
5. GitHub Pagesが `main` / `/` から配信され、公開URLがHTTPSで開けることを確認する。
6. iPhone 16のSafariで公開版またはLAN版を確認する。
7. 現行画像生成GPTの編集権限と共有状態を確認する。設定本文やリンクは公開GitHubへ転記しない。
8. 非公開バックアップの版とハッシュを、公開品質ログの記録と照合する。

この確認に失敗した場合、変更を始めず、差分と影響を整理してプロジェクト責任者へ報告する。

## 5. 情報の正本

| 情報 | 正本 |
|---|---|
| 選択肢、初期値、指示文規則 | `src/catalog.js`、`src/outfits.js` |
| UI動作、端末保存、プリセット | `src/app.js` |
| 画面構造と見た目 | `index.html`、`styles.css` |
| オフライン資産 | `sw.js` |
| PWAメタデータ | `manifest.webmanifest` |
| 実装契約 | `tests/*.test.mjs` と `docs/PWA_SPECIFICATION.md` |
| 公開版番号 | `package.json` |
| 画像品質の公開記録 | `docs/IMAGE_QUALITY_LOG.md` |
| GPTの完全な設定 | 公開GitHub外の暗号化された非公開バックアップ |

公開文書と実装が食い違う場合、無断で片方へ寄せない。差分を調査し、意図を確認したうえで、実装・試験・文書を同じ変更単位で更新する。

## 6. 役割と承認

小規模運用では同じ人が複数役を担当してよいが、判断は区別する。

- プロジェクト責任者: 仕様、品質、廃止、不可逆操作を承認する。
- PWA保守担当: 実装、試験、公開、復旧、文書更新を行う。
- GPT保守担当: 非公開設定のバックアップ、変更、復旧を行う。
- 品質確認者: 独立した新規会話で生成結果を目視評価する。

次は別々の承認として扱う。

- 仕様案の採用
- PWAまたはGPTの変更
- GitHubへのマージと公開
- 画像品質の合格
- GPTの共有停止または削除

## 7. 公開記録に残してはいけない情報

- 実際のIPアドレス、SSID、端末内パス
- 認証情報、Cookie、トークン
- 非公開GPTのInstructions・Knowledge本文
- 非公開GPTの編集用・共有用リンク
- ユーザーの個人情報を含む生のフィードバック
- 添付画像の保存先や個人情報を含む画像

公開ログには、版、ハッシュ、変更目的、個人を特定できない要約、一般化した試験条件、判定だけを記録する。

## 8. 引き継ぎ完了条件

- 後任が自分の環境で自動試験を成功させた。
- 後任がローカル版と公開版の基本操作を確認した。
- 後任がPagesの配信元と公開確認方法を説明できる。
- 後任が保存形式とService Worker更新規則を説明できる。
- 後任がGPT設定本文をGitHubへ保存しない理由と保管場所を理解した。
- 後任が品質試験、承認、ロールバックの手順を説明できる。
- 前任と後任が権限移管を確認し、共有パスワードが存在しない。

引き継ぎ完了後も、不要になった前任者の権限はプロジェクト責任者の承認を得て個別に解除する。
