# PWA仕様書

## 1. 製品概要

本PWAは、架空の20代の成人日本人女性を対象に、人物画像生成用の日本語指示文を選択式で作成する完全クライアント処理型PWAである。写真・アニメのモードを分けず、単一の `index.html` で画風非依存の共通指示文を生成する。画風は出力先の画像生成GPTが決定する。

- 現行開発版: 8.0.0
- 公開版確認: 自動試験19件、393×852相当のブラウザー確認、GitHub Pages配信資産の8.0.0・`7days-v17`・単一統合構成確認に合格。iPhone 16実機Safari確認は未実施
- 6.2.0実機確認: 2026-08-15、iPhone 16 Safariでユーザー確認に合格
- 6.2.0画像品質確認: 2026-08-15、同一基準指示文を写真用画像生成GPTの独立した新規会話3件へ投入し、ユーザー目視で3枚すべて合格
- 7.0.0アニメ画像品質確認: 2026-08-15、「アニメ人物イラスト 新規生成GPT v2」の生成画像をユーザーが目視し、品質合格・正式採用
- 主対象: iPhone 16のSafari
- 配信: GitHub Pages
- 外部API、データベース、分析、広告、外部フォント: 使用しない
- 端末保存: 前回値と名前付きプリセットのみ

## 3. 入力仕様

### 3.1 固定文

統合版は、指示文の先頭へ次の2文だけを固定出力する。容姿、体型、フォトリアル、アニメ、個別画風は含めない。

```text
画像を新規生成する。
被写体は、架空の20代の成人日本人女性1人とする。
```

### 3.2 人物

- バスト: 4択。初期値は「豊かなバスト（89cm相当）」
- ヒップ: 4択。初期値は「標準的なヒップ（85cm相当）」

容姿分類と体型分類のプルダウンは廃止済みであり、再導入には新しい画像検証とユーザー承認を要する。

### 3.3 衣装

- 衣装タイプ: 「ステージ衣装」「私服」。初期値なし
- 衣装構成: 「上下分離」「上下一体」。衣装タイプ選択後も初期値なし
- ステージ衣装・上下分離: トップスとボトムスは「無し」「おまかせ」と具体候補から選ぶ
- ステージ衣装・上下一体: 24種類
- 私服・上下分離: トップスとボトムスは「無し」「おまかせ」と具体候補から選ぶ。旧下着候補は一般衣装一覧から除外する
- 私服・上下一体: 具体候補に加えて「おまかせ」を選べる。「無し」は選べない
- 衣装色: 「無し」「おまかせ」と共通110色。具体色を選ばない指定を許容する
- 色の初期値: アウター・トップス・上下一体はホワイト、ボトムスはチャコールグレー、靴はブラック
- アウターは上下分離・上下一体共通。「無し」「おまかせ」と具体候補から選ぶ
- 上半身用と下半身用の下着は各13択（無し、おまかせ、具体候補11種類）。色の初期値はホワイト
- 上下分離でトップスまたはボトムスが「無し」の場合、対応する下着を主衣装として出力する。衣装が存在する場合、下着はその内側へ着用する
- 上下一体衣装では下着を常に衣装の内側へ着用する
- 下着だけが主衣装の場合は衣装装飾文を出力しない
- 靴は全衣装共通。「無し（裸足）」「おまかせ」と具体候補から選ぶ
- ステージ衣装へコルセット、スカート・パンツ・ドレス候補を追加する
- 私服へ一般衣装、ビキニ、ワンピース水着、競技用水着を収録する
- 私服の上下一体へ、承認済みコンセプト衣装8種類を収録する
- 衣装装飾の初期値: 「内容は衣装に合わせておまかせ、装飾量は控えめ」

衣装タイプまたは衣装構成が未選択なら、後続の衣装項目を表示せず、衣装行も出力しない。組み合わせ確定時は該当一覧の1番を自動選択する。

### 3.4 目・口・髪

- 髪色: 共通110色。初期値はナチュラルブラウン
- 髪型: 26種類。UI表示名と正式な出力語句を分離
- 前髪: 9種類。初期値は流し前髪
- 目の形: 6択。初期値はアーモンド型
- 目の表現: 18択。初期値は真剣
- 特殊な目の表現: 10択。初期値は無し。選択時は必要な範囲で通常の目の形・表現より優先する
- 瞳の色: 共通110色。初期値はナチュラルブラウン
- 口の表現: 24択。初期値は自然な閉じ口

### 3.5 撮影設定

- ポーズ: 必須45択。初期値は自然な直立姿勢
- 構図: 必須7択。「全身」「全身遠景」「太もも上」「腰上」「バストアップ」「肩上」「顔アップ」。初期値は全身
- カメラアングル: 必須7択。「目線の高さ」「やや上」「俯瞰」「真上」「やや下」「ローアングル」「床面」。初期値は目線の高さ
- 撮影方向: 必須4択。初期値は正面
- 背景: 必須19択。初期値は純白のスタジオ
- 照明: 必須32択。オーソドックス、明るい、暗い、独特・演出の4系統を各8種類収録。初期値はニュートラル拡散光

## 4. 指示文出力契約

出力順は次のとおりとし、各項目を半角スペースで連結した1行の文章として出力する。選択肢の出力語句に改行が混入した場合も削除する。

1. 冒頭の固定文2文
2. 目の形、目の表現、特殊な目、瞳色、口の表現、バスト、ヒップ
3. アウター、衣装本体、下着、衣装装飾、靴（衣装選択時のみ）。衣装タイプと構成の独立文は出力せず、衣装文へ用途を含める
4. 髪色、髪型、前髪
5. ポーズ、構図、カメラアングル、撮影方向、背景、照明
6. 画像比率、全身構図時の接地影、禁止要素

特殊な目の表現が「無し」の場合はその文を省略する。全身構図では接地影を出力する。画面の文数表示は句点の数を基準とする。

6.0.1以降は、主語が切り替わる最初の文で主語を明示し、同じ主語が続く文では重複する主語を省略する。意味と述語は維持し、すべての文を句点で終える。衣装装飾が「無し」の場合は `装飾は付けない。` と明示する。6.1.0ではフォトリアル指定を削除して撮影方向を追加し、6.2.0では文間の実改行を削除する。

## 5. UI・アクセシビリティ要件

- 393×852 CSS px相当の縦画面を主基準とする。
- `viewport-fit=cover` とsafe areaを考慮する。
- 操作領域は44px以上、入力文字は16px以上とする。
- 横スクロールを発生させない。
- 一般項目はプルダウン、色は名称とカラーチップを組み合わせて表示する。
- ページ内でプリセットを選択してもスクロール位置を移動しない。
- コピー、保存、読込、削除の完了を画面内通知で示す。
- 固定操作バーはsafe area直上の画面最下部へ配置し、左からリセット、コピーの順で幅比を1:1とする。
- ヘッダーは製品名だけを表示する。
- コピーとリセットを画面下部のアイコン操作バーへ固定し、読み上げ名称を設定する。
- 関連項目を淡い同色の枠でグループ化し、条件分岐後に空の枠を残さない。

Chromiumのモバイル表示はレイアウト確認であり、iPhone実機Safari確認の代替にはしない。

## 6. 端末保存仕様

統合版は保存形式v1を使用する。

- 前回値: `7days:unified:last-values:v1`
- プリセット: `7days:unified:presets:v1`
- スキーマ版: `7days:unified:schema-version`

初回起動時に統合データが存在しない場合だけ、旧写真版v8の前回値とプリセットを移行する。削除された表情や衣装候補は対応する新項目へ写し、統合選択肢に存在しない値は有効な初期値へフォールバックする。旧キーは削除せず、統合データを二回目以降に上書きしない。

## 7. オフライン仕様

Service Workerは主要静的資産を事前キャッシュし、旧キャッシュをactivate時に削除する。8.0.0のキャッシュ名は `7days-v17` である。

キャッシュ対象のファイル内容または一覧を変更した場合は、キャッシュ名も更新する。更新しないと、公開後も旧資産が表示される可能性がある。

## 8. セキュリティとプライバシー

- 入力値とプリセットを端末外へ送信しない。
- 外部スクリプト、外部フォント、分析タグを読み込まない。
- GitHubへ認証情報や非公開GPT設定を保存しない。
- 公開文書の禁止事項は `HANDOFF.md` を適用する。

## 9. 変更時の影響範囲

| 変更 | 主な更新対象 | 必須確認 |
|---|---|---|
| 選択肢・初期値・出力語句 | `src/unified-catalog.js`、`anime-shooting.js` または `outfits.js` | 統合prompt試験、文順、Excel台帳、公開版コピー結果 |
| 項目構造 | 上記に加えて `src/app.js`、`src/mode-config.js` | 保存形式更新の要否、旧データ処理 |
| UI・見た目 | `index.html`、`styles.css`、`src/app.js` | 393×852、実機Safari、スクロール維持 |
| 静的資産 | 対象ファイル、`sw.js` | キャッシュ名と資産一覧 |
| PWAメタデータ | `manifest.webmanifest` | インストール、アイコン、起動 |
| 公開版更新 | `package.json`、README、関連文書 | 自動試験、Pages、実機確認 |

実装、試験、版、文書は同じPull Requestで整合させる。

## 10. 合格条件

- `npm test` が全件成功する。
- ローカル環境で指示文、コピー、プリセット、条件付き衣装が動作する。
- 公開版の主要資産と版が一致する。
- UIまたは挙動変更時はiPhone 16実機Safariで合格する。
- 画像品質に影響する変更時は `GPT_OPERATIONS.md` の独立3件試験でユーザーが明示的に合格する。

## 11. 選択肢Excel台帳

人が閲覧する選択肢一覧は [`7days_options_catalog.xlsx`](7days_options_catalog.xlsx) を台帳とし、Web版カタログは廃止する。動作上の正本は `unified-catalog.js`、`catalog.js`、`anime-shooting.js`、`outfits.js` と契約試験である。8.0.0の統合項目はExcelへ未反映であり、更新完了まではコードと契約試験を参照する。選択肢、初期値、UI表示名、出力語句、色チップを変更した場合は、コード・試験と同じ変更単位でExcel台帳を更新して照合する。
