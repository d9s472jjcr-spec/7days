# PWA仕様書

## 1. 製品概要と文書状態

本PWAは、架空の20代の成人日本人女性を対象に、人物画像生成用の日本語指示文を選択式で作成する完全クライアント処理型PWAである。写真・アニメのモードを分けず、単一の `index.html` で画風非依存の共通指示文を生成する。画風は出力先の画像生成GPTが決定する。

- 現行公開版: 9.0.0
- 9.0.0の状態: 自動試験32件、393×852相当のブラウザー操作確認、PR #35の`main`へのマージ、GitHub Pagesでの9.0.0・`7days-v18`配信確認まで完了
- 実機確認: 2026-08-21にiPhone 16実機Safariでユーザーが公開版を確認し、良好と判定
- 主対象: iPhone 16のSafari
- 配信方式: GitHub Pages
- 外部API、データベース、分析、広告、外部フォント: 使用しない
- 端末保存: 前回値の自動保存のみ
- 画像生成GPT: 9.0.0作業では変更しない

この文書の9.0.0記述は、承認済みの実装契約と、ローカル検証、コミット、マージ、公開、実機確認まで完了した現行状態を記録する。

### 3.3 身体寸法スライダー

| 項目 | 範囲 | 刻み | 初期値 |
|---|---:|---:|---:|
| 身長 | 140〜175cm | 1cm | 158cm |
| バスト | 70〜100cm | 1cm | 81cm |
| ウエスト | 50〜65cm | 1cm | 57cm |
| ヒップ | 75〜95cm | 1cm | 82cm |

初期状態ではバスト、ウエスト、ヒップを身長へ連動させる。身長変更時は、連動中の項目だけを次式で再計算して整数へ丸める。`d = 身長 - 158` とする。

```text
バスト = 81 + (458 / 1071) × d - (1 / 1071) × d²
ウエスト = 57 + (155 / 1071) × d + (2 / 1071) × d²
ヒップ = 82 + (310 / 1071) × d + (4 / 1071) × d²
```

代表値は、身長140cmで73/55/78、158cmで81/57/82、175cmで88/60/88となる。

- バスト、ウエストまたはヒップを手動変更した場合、その項目だけ身長連動を解除する。
- 他の寸法の連動状態は変更しない。
- 各寸法の「身長基準に戻す」で、その項目を再計算して連動状態へ戻す。
- 基準設定へのリセットでは、全寸法を初期値へ戻し、3項目すべてを連動状態へ戻す。
- 数値と連動状態は前回値として端末内へ自動保存する。

### 3.4 寸法の定型表現

バストは次の区分とする。

- 70〜78cm: 控えめ
- 79〜82cm: 標準的
- 83〜91cm: 豊か
- 92〜100cm: とても豊か

ウエストは次の区分とする。

- 50〜57cm: 細め
- 58〜65cm: 標準的

ヒップは次の区分とする。

- 75〜79cm: 控えめ
- 80〜85cm: 標準的
- 86〜90cm: 豊か
- 91〜95cm: とても豊か

### 3.5 推定カップ

推定カップはUIと生成文へ表示する。保存値は持たず、身長、バストまたはウエストが変わるたびに再計算する。ヒップは計算に使用しない。

1. 身長基準アンダーバストを、140〜158cmは61.5〜65.5cm、158〜165cmは65.5〜66.7cmで線形補間し、165〜166cmは66.7cm、166〜175cmは66.7〜69.0cmで線形補間する。
2. 3.3の身長基準ウエストの丸め前値を求める。
3. `推定アンダーバスト = 身長基準アンダーバスト + (表示ウエスト - 身長基準ウエストの丸め前値) × 0.2` とする。
4. `表示バスト - 推定アンダーバスト` を次の境界へ適用する。

| 差 | 推定カップ |
|---:|---|
| 7.5cm未満 | AAA |
| 10cm未満 | AA |
| 12.5cm未満 | A |
| 15cm未満 | B |
| 17.5cm未満 | C |
| 20cm未満 | D |
| 22.5cm未満 | E |
| 25cm未満 | F |
| 27.5cm未満 | G |
| 30cm未満 | H |
| 32.5cm未満 | I |
| 32.5cm以上 | J以上 |

初期値158/81/57/82では「推定Cカップ相当」とする。アンダーバストの推定値自体はUIと生成文へ表示しない。

UI表示例:

```text
81cm｜標準的｜推定Cカップ相当
```

生成文例:

```text
身長158cm、バストは標準的なCカップ相当（81cm）、ウエストは細め（57cm）、ヒップは標準的（82cm）とする。
```

### 3.6 目・口

- 目の形: 6択。初期値はアーモンド型
- 目の表現: 18択。初期値は真剣
- 特殊な目の表現: 10択。初期値は無し
- 瞳の色: 共通色。初期値はナチュラルブラウン
- 口の表現: 24択。初期値は自然な閉じ口

### 3.7 衣装

衣装、アウター、下着、装飾、靴の選択機能と条件分岐は維持する。ただし、生成文ではUIの分類名や制御用語をそのまま読み上げない。

次のような独立文は出力しない。

- `衣装タイプは私服。`
- `構成は上下一体。`
- `私服向けの上下一体衣装は〜。`

実際に着用する内容だけを自然な文章へまとめる。

```text
ホワイトのブラウスとチャコールグレーのスラックスを着用する。
ホワイトのシャツワンピースを着用する。
下着としてホワイトのブラジャーとショーツを着用する。
ホワイトのブラジャーとショーツを着用する。
```

- 上下分離ではトップス、ボトムスと各色を自然に合成する。
- 上下一体では衣装名と色だけを自然に記述する。
- 主衣装がある場合、選択された下着は衣装の内側へ着用する。
- 対応する主衣装が「無し」の場合、選択された下着だけを着用内容として出力する。
- 下着だけが主衣装の場合は衣装装飾文を出力しない。
- 衣装タイプまたは構成が未選択なら、後続の衣装項目を表示せず、衣装文も出力しない。

## 4. 削除対象

9.0.0では、人物の外見そのものに関係しない次の項目をUIと生成文から削除する。

- ポーズ
- 撮影構図
- カメラ位置・角度
- 撮影方向
- 背景
- 照明
- 縦横比
- 接地影
- 文字、ロゴ、不要物などの撮影用禁止事項

名前付きプリセットの保存、読込、削除、プリセット通知、関連UIも削除する。

## 5. 指示文出力契約

- 実改行を含まない1行の日本語文章として出力する。
- 文の境界は句点と半角スペースで表す。
- 同じ情報を別表現で重複させない。
- UIのセクション名、分類名、制御用語をそのまま出力しない。
- 主語が変わる箇所だけ主語を明示し、同じ主語が続く場合は自然に省略する。
- UI項目順を機械的に読み上げず、人物像として自然な順序へ再構成する。
- 特殊な目の表現が「無し」の場合はその文を省略する。
- 特殊な目の表現を選んだ場合は、その特殊表現だけを出力し、通常の目の形、目の表現、瞳色は重複出力しない。
- 人物の特徴は簡潔な自然文へ変換する。
- 身長、バスト、推定カップ、ウエスト、ヒップは重複させず1文へ統合する。
- 衣装は3.7の条件に従い、実際の着用内容だけを出力する。

## 6. UI・アクセシビリティ要件

- 393×852 CSS px相当の縦画面を主基準とする。
- `viewport-fit=cover` とsafe areaを考慮する。
- 操作領域は44px以上、入力文字は16px以上とする。
- 横スクロールを発生させない。
- 一般項目はプルダウン、色は名称とカラーチップを組み合わせて表示する。
- 身体寸法は現在値、範囲、連動状態、個別復帰操作が判別できるスライダーとする。
- 推定カップはバスト付近へ読み取り専用で表示する。
- コピー完了を画面内通知で示す。
- 固定操作バーはsafe area直上の画面最下部へ配置し、左からリセット、コピーの順で幅比を1:1とする。
- ヘッダーは製品名だけを表示する。
- 関連項目を淡い同色の枠でグループ化し、条件分岐後に空の枠を残さない。

Chromiumのモバイル表示はレイアウト確認であり、iPhone実機Safari確認の代替にはしない。

## 7. 端末保存と移行

- 前回値の自動保存を維持する。
- 9.0.0は `7days:unified:last-values:v2` とスキーマ版 `2` を使用する。
- 9.0.0用の保存形式へ、互換性のある髪、目、衣装、下着、靴などを非破壊で移行する。
- 移行元は旧統合v1を優先し、旧統合v1が存在しない場合だけ旧写真v8を使用する。
- 旧バスト選択肢は代表値79/84/89/94cmへ移行する。
- 旧ヒップ選択肢は代表値80/85/90/95cmへ移行する。
- 新しい身長とウエストは158cmと57cmを初期値とする。移行された明示的なバストとヒップは手動値として身長連動を解除し、新規のウエストは身長連動を有効にする。新規起動時はバスト、ウエスト、ヒップをすべて身長連動とする。
- 旧プリセットデータは削除せず、9.0.0から読み書きしない。
- 統合済みの9.0.0データを二回目以降の起動で旧データから上書きしない。

旧キーと旧プリセットキーは削除しない。現行v2が存在するときは、二回目以降の起動で旧データを再移行しない。

## 8. オフライン仕様

Service Workerは主要静的資産を事前キャッシュし、旧キャッシュをactivate時に削除する。キャッシュ対象のファイル内容または一覧を変更した場合は、キャッシュ名も更新する。

9.0.0のService Workerキャッシュ名は `7days-v18` とする。公開前に `package.json`、README、仕様書、配信資産の一致を再確認する。

## 9. セキュリティとプライバシー

- 入力値を端末外へ送信しない。
- 外部スクリプト、外部フォント、分析タグを読み込まない。
- GitHubへ認証情報や非公開GPT設定を保存しない。
- 公開文書の禁止事項は `HANDOFF.md` を適用する。
- Excelを含む別形式の選択肢台帳は利用、更新、照合しない。

## 12. 選択肢管理

選択肢、初期値、UI表示名、出力語句、色チップは、`src/` の実装と `tests/` の契約試験を正本とする。変更時はコードと試験を同じ変更単位で更新し、公開版のコピー結果まで照合する。Excelを含む別形式の選択肢台帳は運用しない。
