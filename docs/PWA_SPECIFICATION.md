# PWA仕様書

## 1. 製品概要

本PWAは、架空の20代の成人日本人女性を対象に、人物画像生成用の日本語指示文を選択式で作成する完全クライアント処理型PWAである。単一の `index.html` 内で写真モード「神は7日で世界を作った」とアニメモード「3日くらい休んでいいのに」を切り替える。PWAは画風を固定せず、出力先の画像生成GPTがフォトリアルまたはアニメイラストの画風を決定する。

- 現行公開版: 6.2.0
- ローカル開発候補: 7.0.0。自動試験67件に合格、未コミット・未公開
- 公開確認: 自動試験46件、GitHub Pagesデプロイに合格
- 実機確認: iPhone 16 Safariでの6.0.1公開後確認に合格
- 6.2.0実機確認: 2026-08-15、iPhone 16 Safariでユーザー確認に合格
- 6.2.0画像品質確認: 2026-08-15、同一基準指示文を現行画像生成GPTの独立した新規会話3件へ投入し、ユーザー目視で3枚すべて合格
- 主対象: iPhone 16のSafari
- 配信: GitHub Pages
- 外部API、データベース、分析、広告、外部フォント: 使用しない
- 端末保存: 前回値と名前付きプリセットのみ

## 3. 入力仕様

### 3.1 固定文

写真版は、指示文の先頭へ常に次の4文を出力する。同一主語が続く文は主語を省略する。画風は出力しない。

```text
画像を新規生成する。
被写体は、架空の20代の成人日本人女性1人とする。
容姿は、美人とする。
体型は、脚の長いモデル体型とする。
```

アニメ版は次の2文だけを固定出力する。容姿、体型、フォトリアル、アニメ、個別画風は固定文へ含めない。

```text
画像を新規生成する。
被写体は、架空の20代の成人日本人女性1人とする。
```

### 3.2 人物

- バスト: 4択。初期値は「豊かなバスト（89cm相当）」
- ヒップ: 4択。初期値は「標準的なヒップ（85cm相当）」

容姿分類と体型分類のプルダウンは廃止済みであり、再導入には新しい画像検証とユーザー承認を要する。

### 3.3 衣装

- 衣装タイプ: 「ステージ衣装」「私服・その他衣装」。初期値なし
- 衣装構成: 「上下分離」「上下一体」。衣装タイプ選択後も初期値なし
- ステージ衣装・上下分離: トップス24種類、ボトムス44種類
- ステージ衣装・上下一体: 24種類
- 私服・その他衣装・上下分離: トップス33種類、ボトムス50種類
- 私服・その他衣装・上下一体: 36種類
- 衣装デザイン総数: 211種類
- 色: 共通110色
- 色の初期値: アウター・トップス・上下一体はホワイト、ボトムスはチャコールグレー、靴はブラック
- アウターは上下分離・上下一体共通。「無し」の場合は色項目と指示文を省略する
- 靴は全衣装共通。初期値はパンプス。「裸足」の場合は色項目を非表示にし「足元は裸足」と出力する
- ステージ衣装へコルセット、スカート・パンツ・ドレス候補を追加する
- 私服・その他衣装へ一般衣装、下着、ビキニ、ワンピース水着、競技用水着を収録する
- 私服・その他衣装の上下一体へ、承認済みコンセプト衣装8種類を収録する
- 衣装装飾の初期値: 「内容は衣装に合わせておまかせ、装飾量は控えめ」

衣装タイプまたは衣装構成が未選択なら、後続の衣装項目を表示せず、衣装行も出力しない。組み合わせ確定時は該当一覧の1番を自動選択する。

### 3.4 髪・瞳

- 髪色: 共通110色。初期値はナチュラルブラウン
- 髪型: 26種類。UI表示名と正式な出力語句を分離
- 前髪: 9種類。初期値は流し前髪
- 瞳の色: 共通110色。初期値はナチュラルブラウン
- アニメ版の目の形: 「アーモンド型」「丸目」「切れ長」「つり目」「たれ目」「三白眼」の6択。前髪の後、瞳色の前に表示し、アーモンド型を初期値とする
- 写真版には目の形項目を追加しない

### 3.5 写真版の撮影設定

- 表情: 必須4択。「真剣」「喜び」「怒り」「悲しみ」
- 表情の初期値: 真剣
- ポーズ: 必須12択。初期値は自然な直立姿勢。成立に不要な腕・手の指定は含めない
- 構図: 必須4択。初期値は全身
- カメラアングル: 必須3択。初期値は目線の高さ。カメラの高さだけを指定する
- 撮影方向: 必須4択。「正面」「斜め45度」「真横」「背面」。初期値は正面
- 背景: 必須19択。初期値は純白のスタジオ
- 照明: 必須16択。オーソドックス、明るい、暗い、独特の4系統を各4種類収録。初期値はニュートラルな拡散照明

### 3.6 アニメ版の撮影設定

- 表情: 必須16択。初期値は真剣。目の形を顔立ちの基礎として保持し、表情による眉、まぶた、視線、開閉の変化を優先する
- ポーズ: 必須45択。初期値は自然な直立姿勢
- 構図: 必須7択。「全身」「全身遠景」「太もも上」「腰上」「バストアップ」「肩上」「顔アップ」。初期値は全身
- カメラアングル: 必須7択。「目線の高さ」「やや上」「俯瞰」「真上」「やや下」「ローアングル」「床面」。初期値は目線の高さ
- 撮影方向: 写真版と共有する必須4択。初期値は正面
- 背景: 写真版と共有する必須19択。初期値は純白のスタジオ
- 照明: 必須32択。オーソドックス、明るい、暗い、独特・演出の4系統を各8種類収録。初期値はニュートラル拡散光

## 4. 指示文出力契約

出力順は次のとおりとし、各項目を半角スペースで連結した1行の文章として出力する。選択肢の出力語句に改行が混入した場合も削除する。

1. 冒頭の固定文。写真版4文、アニメ版2文
2. バスト、ヒップ
3. 衣装タイプ、衣装構成、アウター、衣装本体、衣装装飾、靴（衣装選択時のみ）
4. 髪色、髪型、前髪、アニメ版のみ目の形と優先規則、瞳の色
5. 表情、ポーズ、構図、カメラアングル、撮影方向、背景、照明
6. 画像比率、全身構図時の接地影、禁止要素

写真版、アニメ版とも、初期状態は21文、アウター無し・靴ありの上下分離は27文、上下一体は26文である。アウター選択時は1文増える。写真版は全身だけ、アニメ版は全身と全身遠景だけ接地影を出力する。画面の文数表示は句点の数を基準とする。

6.0.1以降は、主語が切り替わる最初の文で主語を明示し、同じ主語が続く文では重複する主語を省略する。意味と述語は維持し、すべての文を句点で終える。衣装装飾が「無し」の場合は `装飾は付けない。` と明示する。6.1.0ではフォトリアル指定を削除して撮影方向を追加し、6.2.0では文間の実改行を削除する。

## 5. UI・アクセシビリティ要件

- 393×852 CSS px相当の縦画面を主基準とする。
- `viewport-fit=cover` とsafe areaを考慮する。
- 操作領域は44px以上、入力文字は16px以上とする。
- 横スクロールを発生させない。
- 一般項目はプルダウン、色は名称とカラーチップを組み合わせて表示する。
- ページ内でプリセットを選択してもスクロール位置を移動しない。
- コピー、保存、読込、削除の完了を画面内通知で示す。
- 固定操作バーはsafe area直上の画面最下部へ配置し、左からリセット、モード切替、コピーの順で幅比を1:1:2とする。
- モード切替は写真モードにブラシ、アニメモードにカメラのアイコンを表示し、読み上げ名称と切替先を示すtitleを付ける。
- ヘッダーは製品名だけを表示する。
- コピーとリセットを画面下部のアイコン操作バーへ固定し、読み上げ名称を設定する。
- 関連項目を淡い同色の枠でグループ化し、条件分岐後に空の枠を残さない。

Chromiumのモバイル表示はレイアウト確認であり、iPhone実機Safari確認の代替にはしない。

## 6. 端末保存仕様

写真版は6.2.0の保存形式v8を維持する。

- 前回値: `7days:last-values:v8`
- プリセット: `7days:presets:v8`
- スキーマ版: `7days:schema-version`

アニメ版は写真版と重複しない保存形式v1を使用する。

- 前回値: `7days:anime:last-values:v1`
- プリセット: `7days:anime:presets:v1`
- スキーマ版: `7days:anime:schema-version`

モード切替時にページ再読込やURL遷移を行わず、状態を初期化しない。履歴APIでアニメモードを `?mode=anime` として表し、再読込と戻る・進むでもモードを復元する。各モードは他方の保存キーを読み書き・削除しない。

項目追加、削除、値の改名などで既存データの解釈が変わる場合、ユーザーから個別の移行要望がない限り旧プリセットを引き継がない。新しい版のキーとスキーマを採用し、旧キーを初回起動時に削除する。移行を実装する場合は、変換規則と失敗時動作を仕様・試験へ追加する。

## 7. オフライン仕様

Service Workerは主要静的資産を事前キャッシュし、旧キャッシュをactivate時に削除する。公開版6.2.0のキャッシュ名は `7days-v14`、ローカル候補7.0.0は `7days-v16` である。クエリ付きでアニメモードを再読込した場合も、単一の `index.html` をオフライン応答へ使用する。

キャッシュ対象のファイル内容または一覧を変更した場合は、キャッシュ名も更新する。更新しないと、公開後も旧資産が表示される可能性がある。

## 8. セキュリティとプライバシー

- 入力値とプリセットを端末外へ送信しない。
- 外部スクリプト、外部フォント、分析タグを読み込まない。
- GitHubへ認証情報や非公開GPT設定を保存しない。
- 公開文書の禁止事項は `HANDOFF.md` を適用する。

## 9. 変更時の影響範囲

| 変更 | 主な更新対象 | 必須確認 |
|---|---|---|
| 選択肢・初期値・出力語句 | 対象モードのcatalog、`anime-shooting.js` または `outfits.js` | 対応するprompt試験、文順、Excel台帳、公開版コピー結果 |
| 項目構造 | 上記に加えて `src/app.js`、`src/mode-config.js` | 保存形式更新の要否、モード間分離、旧データ処理 |
| UI・見た目 | `index.html`、`styles.css`、`src/app.js`、`src/mode-config.js` | 393×852、実機Safari、同一画面切替、スクロール維持 |
| 静的資産 | 対象ファイル、`sw.js` | キャッシュ名と資産一覧 |
| PWAメタデータ | `manifest.webmanifest` | インストール、アイコン、起動 |
| 公開版更新 | `package.json`、README、関連文書 | 自動試験、Pages、実機確認 |

実装、試験、版、文書は同じPull Requestで整合させる。

## 10. 合格条件

- `npm test` が全件成功する。
- ローカル環境で指示文、コピー、プリセット、条件付き衣装が動作する。
- 公開版の主要資産と版が一致する。
- UIまたは挙動変更時はiPhone 16実機Safariで合格する。
- 画像品質に影響する変更時は `GPT_OPERATIONS.md` の独立3件試験でユーザーが明示的に合格する。

## 11. 選択肢Excel台帳

人が閲覧する選択肢一覧は [`7days_options_catalog.xlsx`](7days_options_catalog.xlsx) を正規台帳とし、Web版カタログは廃止する。動作上の正本は各catalog、`anime-shooting.js`、`outfits.js` と契約試験である。選択肢、初期値、UI表示名、出力語句、色チップを変更した場合は、コード・試験と同じ変更単位でExcel台帳を更新して照合する。
